# Legacy Migration Strategy & Audit Analysis

## 1. Legacy Repository Audit

The legacy Expense Tracker application consists of three static client-side files (`index.html`, `script.js`, `style.css`) with total lines of code under 200.

| Artifact | Current Purpose | Limitations & Critical Flaws | Modernization Decision |
| :--- | :--- | :--- | :--- |
| `index.html` (62 lines) | Static HTML markup with two inline-toggled views: "Expense Mode" and "Monthly Overview Mode". | Uses obsolete inline event handlers (`onclick="calculateExpense()"`), missing semantic tags, unlabelled inputs, unstyled buttons, no accessibility (WCAG violations), and no responsive breakpoints. | **REPLACE**: Rebuild as Next.js App Router layout and modular view components using semantic HTML, accessible form primitives, and Tailwind CSS. |
| `script.js` (94 lines) | Global JS logic containing split calculation, date-keyed `localStorage` persistence, and raw `jspdf` report generation. | - **Floating Point Arithmetic**: Uses `parseFloat` directly, causing precision inaccuracies.<br>- **Primitive Data Model**: `monthlyData` is an unstructured object keyed by date (`YYYY-MM-DD`), preventing multiple transactions per day and omitting categories, accounts, or payment methods.<br>- **Split Logic Flaw**: Assumes member count equals contribution count; does not handle complex bill splitting or debt settlement.<br>- **Unstyled PDF**: Uses deprecated CDN jsPDF dumping hardcoded unformatted text lines with naive `yOffset += 10`. Breaks on >10 entries. | **MIGRATE & REFACTOR**: Extract the two core features (Expense Splitting and Monthly Overview/Reports), reimplement them with exact minor-unit money math, relational models, multi-category tracking, and professional `pdf-lib` vector rendering. |
| `style.css` (31 lines) | Basic CSS styling with hardcoded purple/pink gradient background, unstyled input fields, and no design system tokens. | High visual fatigue, no dark mode, fixed dimensions (`max-width: 450px`), lacks mobile responsiveness, fails contrast guidelines. | **REPLACE**: Modernize into a cohesive Tailwind v4 design system adhering to the "Asian Apple" soft-minimalist aesthetic with light/dark modes and accessible contrast. |
| `Outputs.pdf` (534 KB) | Sample PDF output from the legacy app. | Demonstrates the plain, unaligned text dump generated by `jspdf` without branding, summary tables, pagination, or visual hierarchy. | **REPLACE**: Superseded by the new executive-grade monthly financial report generator. |

## 2. Component Migration Matrix

Each legacy capability is classified under: **KEEP, MIGRATE, REFACTOR, REPLACE, or REMOVE**.

| Subsystem / Feature | Legacy Status | Modernization Classification | Technical Target & Enhancements |
| :--- | :--- | :--- | :--- |
| **Expense Splitting** (`calculateExpense()`) | Basic equal share computation from comma-separated names and numbers. | **REFACTOR & ENHANCE** | Modernized into a dedicated `/split` module supporting named split groups, unequal shares, exact cent rounding allocation, and an automated debt minimization graph ("who owes whom"). |
| **Monthly Overview Data** (`monthlyData` in localStorage) | Single record per date: `{ income, savings, expenses, remaining }`. | **MIGRATE & UPGRADE** | Upgraded to a normalized relational schema supporting arbitrary transactions per day, categorization, account balances, and automated monthly rollups. | **PDF Generation** (`generateMonthlyPDF()`) | Raw `jspdf` text printing into single canvas. | **REPLACE** | Replaced with server-side / client-compatible `pdf-lib` engine generating multi-page vector documents with executive summary, category tables, budget variance, and paginated transaction ledgers. |
| **Inline CSS & Gradients** | Rigid 3-color linear gradient, dark purple container, neon orange buttons. | **REPLACE** | Replaced with Tailwind CSS tokenized design system: Apple-like typography, soft warm backgrounds, slate surfaces, accessible status badges, and seamless dark mode. |
| **State Persistence** | Direct unstructured `localStorage.setItem('monthlyData')`. | **REPLACE** | Replaced with Prisma ORM relational database (SQLite/PostgreSQL) and TanStack Query caching, backed by client-side IndexedDB for offline resilience. |

## 3. Legacy Data Ingestion & Migration Script

To ensure zero data loss for existing users, an automatic client-side migration adapter will detect legacy `monthlyData` in `localStorage` on first load and port it into the new schema:

```typescript
// Migration Adapter: legacy localStorage -> modern relational schema
export function migrateLegacyLocalStorageData(): {
  migratedCount: number;
  transactions: Array<{
    amountMinor: number;
    type: 'INCOME' | 'EXPENSE';
    date: Date;
    notes: string;
  }>;
} {
  const legacyRaw = localStorage.getItem('monthlyData');
  if (!legacyRaw) return { migratedCount: 0, transactions: [] };

  try {
    const parsed = JSON.parse(legacyRaw) as Record<
      string,
      { income: number; expenses: number; savings: number; remaining: number }
    >;
    const migratedTransactions = [];

    for (const [dateStr, data] of Object.entries(parsed)) {
      const date = new Date(dateStr);
      if (data.income > 0) {
        migratedTransactions.push({
          amountMinor: Math.round(data.income * 100),
          type: 'INCOME' as const,
          date,
          notes: `Migrated legacy income for ${dateStr}`,
        });
      }
      if (data.expenses > 0) {
        migratedTransactions.push({
          amountMinor: Math.round(data.expenses * 100),
          type: 'EXPENSE' as const,
          date,
          notes: `Migrated legacy expenses for ${dateStr}`,
        });
      }
    }

    // Preserve legacy backup before marking migrated
    localStorage.setItem('monthlyData_legacy_backup', legacyRaw);
    localStorage.removeItem('monthlyData');
    return { migratedCount: migratedTransactions.length, transactions: migratedTransactions };
  } catch (err) {
    console.error('Failed to parse legacy localStorage data', err);
    return { migratedCount: 0, transactions: [] };
  }
}
```

## 4. Rollback Strategy

1. **Legacy Backup Preservation**: When legacy `monthlyData` is imported, it is copied to `monthlyData_legacy_backup` so it is never permanently discarded.
2. **JSON Export / Restore**: A full JSON export is provided in the Settings page, allowing users to export their entire transaction ledger, accounts, categories, and budgets at any time and re-import them.
3. **Database Migrations**: Prisma schema migrations are tracked via timestamped migration files, supporting schema rollback if necessary.
